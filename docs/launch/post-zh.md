# 我在手机上批准 AI 的每一次危险操作

> 发布渠道：V2EX（分享创造）/ 少数派 / 即刻
> 配图：首屏放 90 秒 GIF

用 AI 编码工具的人大概都遇到过这个场面：任务跑到一半，它停下来问「要不要执行这条命令」，而你已经出门了。

轻则等回家，重则任务卡在那里几个小时。

我试过几种办法，都不太顺：

- **飞书 / 微信机器人推送**：能收到「需要审批」，但点不了批准，还是得回电脑
- **tmux + 手机 SSH**：能用，但每次都要连、要敲、要认屏幕
- **干脆全放行**：省事，但等于把方向盘扔了

所以我做了这个：控制台放在你自己的机器上，手机用浏览器打开，能看到任务在跑什么，需要批准的直接点。

![演示](待补)

## 它不是聊天客户端，是遥控器

三个设计上的选择：

**一、数据留在自己机器**

控制台是自托管的。项目本身不往任何服务器传东西，你把它放自己电脑、NAS、还是云上，自己决定。

代价是你要自己部署。这个取舍我想了很久，最后还是选了它——一个能远程批准命令的工具，如果还要把会话内容交给第三方，那它解决的问题和制造的问题一样大。

**二、不绑一家工具**

DSH、Codex、Claude Code、Antigravity 都能接。能力不一样，界面按能力显示——做不到的功能不会给你一个点不动的按钮。

**三、审批走工具自己的接口**

不是截屏识别「Y/n」再模拟按键。那种做法界面一改版就废，而且它只知道「它在问」，不知道「它在问什么」。

## 现在能用到什么程度

| | 看会话 | 发指令 | 停止 | 手机审批 |
|---|:---:|:---:|:---:|:---:|
| DSH | ✅ | ✅ | ✅ | ✅ |
| Antigravity | ✅ | ✅ | ✅ | ✅ |
| Claude Code | ✅ | ✅ | ✅ | 计划中 |
| Codex | ✅ | ✅ | ✅ | 计划中 |

Claude Code 官方提供了执行前钩子和权限代理，路径是明确的；Codex 需要切到常驻服务模式，还在探索。

## 怎么开始

```bash
docker run -d --name dsh-hub -p 8080:8080 \
  -e HUB_TOKEN=<你的密码> \
  -v dsh-hub-data:/data \
  ghcr.io/oscarka/dsh-hub:0.3.0
```

打开 `http://localhost:8080`，登录，生成配对码，在电脑上执行一条命令接进来。

想在外面用，后面再加隧道或部署到云上——README 里有对照表。

## 限制也说在前面

- **电脑得开着**。任务在你自己机器上跑，控制台只是中转
- **单人维护**，没有 SLA，不承诺响应时间
- **Railway 部署大约 $5/月**，免费额度撑不住常驻服务
- **Windows 没验证过**，目前面向 macOS 和 Linux
