# 安装验证矩阵

发布前填完这张表。**自己说「支持多架构」不算数，有记录才算。**

## 怎么测

每换一个环境，从零开始，严格照 README 的步骤走，不要用你开发机上的缓存和配置。

记录四件事：

1. **能不能装上**——有没有报错，报什么
2. **多久**——从第一条命令到手机看到界面
3. **卡在哪**——哪一步需要看文档才能继续
4. **屏幕上的码**——配对码和地址是否打印正确

## 每次要覆盖的场景

| 场景 | 预期 |
|---|---|
| 不带 `HUB_TOKEN` 启动 | 明确报错退出，不是静默放行 |
| 带 `HUB_TOKEN` 启动 | 打印地址 + 配对码 + 二维码 |
| 挂载数据卷后重启容器 | 配对记录、设备信任还在 |
| 不挂数据卷重启 | 数据丢失，但**有明确提示**，不是静默清空 |
| 手机扫码登录 | 10 秒内进入控制台 |
| 第二台电脑用同一个码接入 | 成功，界面显示 2 台 |
| 未安装 DSH 的机器接入 | 进入观察模式，界面不显示审批按钮 |
| 配对码过期后再用 | 明确提示已过期，并可重新生成 |

## 结果怎么用

- **任何一行为空** → 发布检查清单里打不了勾
- **某一环境失败** → 要么修，要么在 README 里明确写「不支持这个环境」
- **耗时超过 10 分钟** → 说明文档有问题，回去改步骤，不要怪用户

## 记录方式

测试时直接在这张表里填。发布时把填好的表附在 Release 正文里，用户能看到你到底测过什么。
